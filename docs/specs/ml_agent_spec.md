## 1. 现状代码审计：盲测段数据泄漏风险分析

### 1.1 两个子系统的口径冲突

在当前的系统中，存在一个极其隐蔽但致命的时间窗口口径割裂：

| 模块 | 训练集（Train） | 验证集（Val） | 盲测锁定段（Holdout Test） | LLM 能见度 |
|---|---|---|---|---|
| **单因子自主挖掘（AlphaAgent）** | `2020-01-01` ~ `2022-12-31` | `2023-01-01` ~ `2024-12-31` | **`2025-01-01` ~ 至今** | 严格封死在 2024 年底前。盲测段绝对锁定，LLM 与调优循环完全不可见。 |
| **现状 ML 组合（train_ml_composite.py）** | 历史至 `mining_end`（2024-12-31） | **无**（直接跳过） | **`2025-01-01` ~ 至今** （被拿来做 Walk-Forward 评估） | **严重泄漏隐患**：OOS 折表现与 gate 回测全部算自 2025+，且直接喂给了 LLM 说明书。 |

### 1.2 代码级实证（真实代码追溯）

在 `scripts/train_ml_composite.py` 现状中：
1. **数据右端无截断**（第 263-270 行）：
   ```python
   data_latest = pd.Timestamp(resolve_test_end()) # 取数据源最新交易日（如 2026 年）
   end = pd.Timestamp(args.end) if args.end else data_latest
   ```
2. **Walk-Forward 评估区间强行落入 2025+**（第 359-364 行）：
   ```python
   # 第一折的 OOS 必须完全落在 mining_end（2024-12-31）之后的干净段
   folds = [f for f in folds if pd.Timestamp(f.oos_dates.min()) >= mining_end]
   ```
   **结果**：所有各折的 OOS IC、ICIR、超额夏普、最大回撤、以及 `engine_gate` 可交易性回测，**全部计算于 2025-01-01 至 2026 年的行情数据**！
3. **LLM 间接窥探与多重检验（Data Snooping）**：
   在脚本第 768 行：
   ```python
   summary = llm_summarize_report(report)
   ```
   `report` 中记录的就是 2025+ 的绩效数字。LLM 读了这个报表生成了总结与风险分析。
   **如果用户和 LLM 根据这些结果在前端反复调整因子组合、重试训练，2025+ 的真正盲测段就被彻底当成了验证集（Validation Set）反复调参消耗，导致盲测集被“彻底烧穿”！**

## 2. 防烧盲测的三层物理隔离架构（核心规范）

为捍卫量化回测“样本外绝不可见”的铁律，本 SPEC 规定必须将 ML 组合的工作流强制划分为两个**物理隔离的独立阶段**：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 阶段一：组合研发与流式交互态（ML Agent Interactive Mining / Tuning）       │
│                                                                             │
│  [2020 ~ 2022 组合训练段] ──► [2023 ~ 2024 组合验证段 (OOS)]                 │
│                                           │                                 │
│                                    右端死线：2024-12-31                      │
│                                           │                                 │
│  ★ LLM 思考、因子语义推荐、超参调优、交互式流式输出【只能】看到该区间指标。    │
│  ★ 2025+ 盲测段数据被物理截断，数据加载层直接不读入内存。                   │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │ 用户/Agent 满意，冻结组合
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 阶段二：终审盲测定稿态（Blind Test Delivery Gate）                          │
│                                                                             │
│  [2025-01-01 ~ 最新交易日]                                                 │
│                                                                             │
│  ★ 只有在点击“另存为组合因子”或“提交盲测终审”后触发一次。                    │
│  ★ 纯 Python 引擎确定性计算，【绝对禁止】LLM 介入，【绝对禁止】回流调优。    │
│  ★ 报告一次性归档至 artifacts/alphaagent/composite_blind_test/。             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 参数与数据源约束
1. **研发调优模式下**：
   - `train_ml_composite.py` 必须引入并默认激活 `--eval-mode=tuning`。
   - `end` 日期强制硬上限为 `2024-12-31`（`val_end`）。
   - Walk-forward 划分：以 2020~2022 作为拟合窗，2023~2024 作为 OOS 滚动检验窗。
   - 数据加载 `load_panel_from_cne` 右端截止于 2024-12-31。
2. **LLM 上下文安全保障**：
   - `llm_recommend_subset`：只允许接收因子的硬元数据（名称、facets 标签、表达式结构、入库时间），不得带任何 2025+ 信息。
   - `llm_summarize_report`：接收的 `fold_metrics` 和 `gate` 只能来自 2023~2024 验证段。

## 3. ML 组合智能体（ML Agent）系统设计

### 3.1 用户体验目标（对齐 AlphaAgent）
用户需要的是一个具备**流式思考过程、动态步骤卡片、以及人机协同引导能力**的专属智能体工作台，而非单向的离线批量任务面板。

### 3.3 后端事件总线（SSE 事件契约）
后端复用 `AgentRun` 架构，建立 `/api/alphaagent/ml-runs/{id}/events` 流式总线，支持以下事件推流：

| 事件类型 (`event`) | 说明 | 载荷字段 (`payload`) |
|---|---|---|
| `session_start` | 组合任务启动 | `run_id`, `model`, `params`, `isolation_mode` |
| `agent_thinking` | LLM 实时流式思考增量 | `content` (Markdown 文本) |
| `assistant_tool_call` | 智能体触发执行动作 | `name`, `arguments` (如 `screen_factors`, `train_fold`) |
| `ml_pool_analyzed` | 因子池语义分析与白名单产生 | `recommended`, `dropped`, `rationale`, `pool_fingerprint` |
| `ml_fold_progress` | 实时折级进度推流 | `fold_idx`, `total_folds`, `period`, `model_ics`, `feature_weights` |
| `ml_gate_evaluated` | 验证集 engine_gate 诊断结果 | `passed`, `excess_annual`, `sharpe`, `turnover`, `drawdown` |
| `ml_summary_generated`| 最终组合说明书生成 | `summary`, `strengths`, `risks`, `suggestions` |
| `session_end` | 任务收敛结束 | `status`, `duration_s`, `artifact_paths` |

## 5. 验收与门禁标准

1. **盲测零泄漏断言**：
   - 单元测试验证：在交互式 ML 调优会话中，断言所有喂入 LLM Prompt 的 JSON 结构体中不得包含 `2025`、`2026` 开头的任何日期或评估指标。
   - 断言 `tuning` 模式下 `load_panel_from_cne` 的 `end` 参数不超过 `2024-12-31`。
2. **流式体验验收**：
   - 点击启动后，前端在 1 秒内建立 SSE 连接并开始渲染 `agent_thinking` 打字机流。
   - 每完成一折计算，前端实时更新当前折的 IC 柱状图，无需等待全部折结束。
   - 训练完成自动弹出组合说明书，并支持追加输入自然语言进行迭代调优。
