# 融合因子 × 统一大库重构总计划

> 2026-09-03 立项。目标：让跨数据面融合因子成为一等公民——分类、记忆、入库、
> 展示全链路正确归位；因子库从"按研究模式分库"重构为"单一大库 + facet 标签筛选"。

## 一、背景

数据面聚焦（focus_facets，2026-09-02 上线）打通了前端多选 → 融合指令 → 列族加载
→ 每轮聚焦提醒的链路，但融合因子在**记忆分类、入库元数据、落库路由**三处仍是二等公民：

1. **族分类失真**：`classify_family` 按文本首关键词命中返回，融合表达式的族取决于
   关键词在 `_FAMILY_RULES` 字典序中谁先命中（如 `DIVIDE($funda_roe, TS_STD(...))`
   会因 `std` 排在 `funda_` 前被分为 volatility）。
2. **入库无 facet 元数据**：候选/正式 registry 无 `facets`/`is_fusion` 字段，
   因子库无法辨识、筛选融合因子。
3. **落库路由**：按挖掘模式分库（technical/fundamental），融合因子归属尴尬，
   且跨模式重复因子互相不可见。

用户已拍板（2026-09-03）：**库合并为单一大库，每个因子带 facet 标签，按标签筛选**；
前端展示（Phase 3）单独做。

### 记忆链路事实

- 族分类唯一收口：`memory/expressions.py::classify_family`（写 `ingestion.py:58`、
  读 `advisory.py:60` / `retrieval.py:828` 双侧同函数 → 改一处双侧自动一致）。
- 检索族亲和：`_hybrid_score:225`，`entry.family ∈ focus_families` 精确匹配（+0.3）；
  单面 query ↔ 融合条目的跨召回是真实缺口（facets 重叠可补）。
- 饱和度/SSPM/经验蒸馏全部按 family 聚合 → family 键换成面对组合键后**零改动
  自动按融合对聚合**；早期 n 小 → Eq.7 置信度低 → 先验门静默（优雅降级）。
- **假融合风险（头号，必须先修）**：`FACET_DEFS`（expressions.py:273）中
  价量面 keys 含 `$close/$open/$vwap`、量能面含 `$volume/$amount`、股东面含
  `$float_cap` → 普通量价因子（`$close+$volume`）或市值中性因子会被判为多面，
  不设防则族分类从细粒度退化为粗粒度对键，记忆桶体系失真。
- 融合功能 09-02 才上线，存量 ~1483 条记忆几乎全为单面技术因子 →
  **不需要 backfill**；唯一分裂点（改动前后同表达式的 cells 分键）量级个位数，
  90d half-life 自然衰减。
- 注入预算分段（evidence_reserve）已就位，记忆块数量/长度不受本次改造影响。

### 其它事实

- 库路径唯一派生点：`core/factor_categories.py` 全部从

- research_mode 的真实职责：门槛档位 / label 选择 / panel 列加载 / engine_gate 频率

## 三、已拍板设计决策

| 决策点 | 结论 |
|---|---|
| 库结构 | **单一大库**（candidate_main / production_main），因子带 facet 标签，按标签筛选 |
| 融合族键 | **面对组合键**（如 `基本面×量能面`），仅**跨数据源组**的 ≥2 面判融合；同组多面保持旧 `_FAMILY_RULES` 细粒度分类 |
| 落库路由 | 融合因子随挖掘流程落大库，无模式路由问题（被大库消解） |
| 前端 | Phase 3 单独做，本次不动 |
| 白名单豁免句 | **需要**，放 facet_focus 板块 render 末尾（research_policy_prompt 经 extra_instructions 注入 system prompt，白名单与融合指令矛盾真实存在） |
| research_policy_prompt 死代码 | **非死代码**（在 scripts 接线），保留不动 |
| 存量记忆 backfill | **不做**（存量融合条目 ≈ 0），读取时 expr_facets 现算兜底 |

## 四、Phase 1 —— 记忆与分类地基（库不动）

### 1.1 假融合防线（第一步，expr_facets 地基）

- `expressions.py`：新增 `FACET_GROUPS`（行情组=价量/量能/筹码/拥挤；
  基本面组=基本面/股东；事件资金组=事件/资金），新增 `fusion_pairs(expr)` 或
  在 `expr_facets` 旁提供跨组判定辅助（不动 `expr_facets` 现有语义，
  diversity block / 蒸馏标签 / 聚焦提醒继续用全量面集合）。
- `$float_cap` 移出股东面识别 keys（市值是行情面板列）——同步修正
  diversity block 与蒸馏标签的面计数。
- 验收：`$close+$volume` 因子不产面对键；`funda_+$close` 产 `基本面×价量面`。

### 1.2 classify_family_ex 面对键

- `expressions.py`：`classify_family_ex(name, expr) -> (family, facets)`；
  facets 跨组 ≥2 → family = 面对键（面名按 FACET_DEFS 稳定排序 `×` 连接）；
  否则走旧 `_FAMILY_RULES`。`classify_family()` 改为薄包装（取 family），
  10+ 旧调用方零改动。

### 1.3 记忆层 facets 亲和

- `memory/schema.py`：memory_entries 加 `facets_json` 列（幂等迁移，
  data_version 3→4）；ingestion 写入 facets_json。
- `retrieval.py`：`_hybrid_score` 族亲和改两档——family 精确匹配 +0.3，
  facets 重叠（entry facets ∩ query facets 非空）+0.15（老条目无 facets_json
  时按表达式现算兜底）。

### 1.4 入库 registry 元数据

- `delivery/submit.py`（候选 + 正式 registry / upsert_mining_registry）：
  写 `facets`（JSON list）、`is_fusion`、`family`（新口径）、`eval_label`
  （本次评估 label 列）。
- 读取侧（factors API / 前端）对老条目缺字段按表达式现算兜底，不回填。

### 1.5 facet_focus 插件模块（prompt 插件化后的标准做法）

- 新建 `prompt/modules/facet_focus.py`：`ORDER = 135`（population_mode 130 与
  extra_instructions 140 之间——运行模式指令区，用户指定优先级高）；
  `enabled(ctx)` = `bool(ctx.focus_facets)`；`render(ctx)` 输出融合模式
  （≥2 面时）或单面聚焦指令（单面时），与 CLI 用户消息块、每轮记忆提醒同口径。
- `prompt_modules.py`：`PromptContext` 加一等字段 `focus_facets: tuple[str, ...] = ()`
  （docstring 已预告此运行时事实）。
- `prompts.py::build_system_prompt` 加参数 `focus_facets`，传入 ctx；
  调用方 `agentscope_run.py`（两处）、`agent/run.py:80` 传 `config.focus_facets`。
- `modules/__init__.py` DEFAULT_MODULES 注册一行。
- 三层分工保持：system prompt 板块=约束契约、user message=任务指令（已有）、
  每轮记忆提醒=持续引导（已有）。

### 1.6 清理

- ~~research_policy_prompt 死代码处置~~ → 证实非死代码（extra_instructions 注入链），
  保留不动；豁免声明由 facet_focus 板块承载（已并入 1.5）。

### 1.7 测试

- expressions：FACET_GROUPS 跨组/同组判定、classify_family_ex 三分支
  （融合→对键、单面→旧行为、$float_cap 不再算股东面）。
- 记忆：facets_json 迁移幂等、亲和两档加分、老条目兜底。
- prompt：facet_focus enabled/render（有/无 focus_facets）、装配报告含新模块、
