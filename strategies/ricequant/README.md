# 动量20日 · 科技TMT · Top3 —— 本地引擎 ↔ 米筐(RiceQuant) 对齐手册

## 文件清单

| 文件 | 用途 |
|---|---|
| `mom20_top3_techtmt.py` | 粘贴到米筐在线策略编辑器的策略源码 |

## 一、本地引擎口径（对齐目标）

来源：`core/engine.py::run_backtest` + `backend/routers/backtest.py::BacktestRequest` 默认值。

| 项 | 值 | 说明 |
|---|---|---|
| 策略 | 动量 20 日 | `factor=mom20, ascending=False`，买动量最强的一批 |
| 因子定义 | `close.pct_change(20)` | 前复权收盘价 20 日涨幅（engine.py:54） |
| 股票池 | 科技TMT ∩ 面板 − 创业板/科创板 | tech.csv 90 只（已剔 300/301/688/689） |
| 调仓节奏 | 月末收盘出信号 → 次月首个交易日开盘成交 | engine.py:494,502 |
| 流动性过滤 | `am20 >= 池内当日 20% 分位` 且 `turn20 > 0` | **amount_q=0.2 是路由默认值**，不是引擎签名的 0.3 |
| 选股 | mom20 降序 Top3 等权 | 预算 = 信号日收盘组合总值 ÷ 当期选中数 |
| 执行模型 | 先卖后买、100 股整手向下取整、现金封顶、T+1 | execution.py:115-230 |
| 涨跌停 | 近似识别：涨幅≥限制−0.5% 拒买、跌幅对称拒卖 | limit.py（主板10%，ST 5% 按逐日标记区分） |
| 费用（页面口径） | 买入 0.0008 / 卖出 0.0013，双边最低 5 元（STOCK_PROFILE 默认），滑点 0 | assets.py:32；与米筐镜像口径的差异只剩买卖费率拆分 |
| 复权 | 前复权（qfq），分红已在价格里 | — |
| 预热 | start 前 400 自然日只算因子不输出净值 | warmup_days=400 |

### ⚠️ 最重要的一个坑：初始资金必须是 5000 元

5000 元 ÷ 3 ≈ 1667 元/票 → 股价高于 ~16.6 元的股票整手取整后**买不起被拒**。
本地基线（2024-01~2025-12）21 个调仓月中，多数月份实际只持有 0~2 只，
甚至整月空仓。米筐端资金设成 1 万、10 万，持仓数和净值会完全不同，
对比就失去意义了。

## 二、米筐端操作步骤

1. 新建「股票 · 日频」策略，粘贴 `mom20_top3_techtmt.py`。
2. 回测设置（对照平台表单逐项）：

   | 平台字段 | 设置 | 原因 |
   |---|---|---|
   | 初始资金 | **5000** | 见下方"最重要的坑" |
   | 起止日期 | 与本地导出命令一致 | — |
   | 基准合约 | 000300.XSHG 不动 | 只影响展示曲线；本地基准是池内等权，平台配不出，对比不看它 |
   | 佣金倍率 | **保持 1** | 米筐默认=买卖佣金万三+双边最低5元+卖出印花税千一。倍率只有一个旋钮，调大只会把买入费率推离目标，凑不出本地页面的买8/卖13；正确做法是反向对齐——导出脚本默认已镜像平台模型（`--buy-cost 0.0003 --sell-cost 0.0013 --min-commission 5`） |
   | 撮合方式 | 下拉里若有「开盘价」类选项就选它；没有则保持「当前bar收盘」 | 本地是次日开盘成交；收盘撮合=同样的信号、当天收盘价成交，晚半天，属已知差异#2 |
   | 滑点类型/滑点 | 百分比 / 0 | 与本地 slippage_bps=0 一致 |

3. 运行回测，下载成交记录与每日持仓。
4. 取数 API 自动三级降级：`history`（旧框架）→ `history_bars`（rqalpha 系，
   逐票取各自最近 N 根日 bar 拼表）→ 明确报错。米筐现行框架走第二条，
   无需改动。若两者都缺失，把平台名称发来按其 API 补一条分支即可。

本地重跑同窗口基准（默认即米筐费用镜像口径）：

```powershell
.venv\Scripts\python.exe scripts\ricequant_picks_export.py --start 2024-01-01 --end 2025-12-31

# 如需按本系统回测页的费用口径（买8/卖13/无最低佣金）：
.venv\Scripts\python.exe scripts\ricequant_picks_export.py --start 2024-01-01 --end 2025-12-31 --buy-cost 0.0008 --sell-cost 0.0013 --min-commission 0
```

## 三、对比方法

按顺序比对，第一层不一致就不必看后面：

1. **每月目标持仓**：`baseline/monthly_targets.csv` ↔ 平台每月调仓后持仓。
   不一致 → 查池名单是否同期一致 → 查 am20 分位过滤 → 查 mom20 数值。
2. **逐笔成交**：`baseline/fills.csv` ↔ 平台成交记录。
   对日期、方向、股数；股数差异多半来自预算基准时点（见差异#3）。
3. **拒单**：`baseline/rejections.csv` ↔ 平台废单。
   停牌/涨跌停判定两边规则不同，属预期差异（见差异#4）。
4. **净值曲线**：`baseline/nav.csv` ↔ 平台收益曲线。
   前三层都一致时，曲线差异应只剩费用/撮合价的二阶小量。

## 四、已知不可消除的差异（按影响排序）

1. **数据源不同**：本地 Tushare 前复权 vs 米筐自建复权。除权除息日的
   价格会有细微差别 → 影响因子值边缘排名与成交价。
2. **撮合价格时点**：本地固定次日开盘价成交；米筐撮合方式为「当前bar收盘」
   时，同样的信号在调仓日**收盘价**成交，比本地晚半天。月频调仓下影响有限
   但非零；下拉若有开盘价选项可消除此项。
3. **预算基准时点**：本地按信号日收盘组合总值等分；米筐端
   `order_target_value` 用调仓当日实时组合市值。差一个隔夜波动。
4. **持仓补齐行为**：本地续持股票"只补不剪"（execution.py:205 不减现有
   股数）；`order_target_value` 会把超额部分也卖掉。长期续持时有差异。
5. **涨跌停/ST 规则**：本地用涨跌幅阈值近似，ST 股按逐日标记 5% 区分
   （CNE trading_status，2016 年前窗口降级为板块近似）；平台用精确规则。
   一字板、ST 股的买卖约束可能不同。
6. **换手率字段**：本地 turn20 用换手率均值>0 判定流动性；策略端等价改用
   20 日成交额>0。两者在实际数据上几乎不会产生分歧。
7. **股票池时效**：POOL 名单是当前 tech.csv 快照。本地池更新后需重新
   导出名单并替换策略文件里的 POOL，同时重跑 baseline。

## 七、对齐结论（2024-01-01 ~ 2025-12-31 实测，旧口径基线）

> 注：本节数字基于涨跌停开盘口径改动**之前**的本地基线（当时与米筐收盘
> 撮合行为更接近）。规则改为开盘判定后，执行层假设不同了，结果层分叉
> 属预期——研究层结论不受影响。当前口径的各因子基线见第六节。

| 指标 | 本地引擎 | 米筐 | 差异 |
|---|---|---|---|
| 总收益 | 30.02% | 29.35% | −0.67pp |
| 年化收益 | 14.15% | 14.31% | +0.16pp |
| 夏普 | 0.81 | 0.79 | −0.03 |
| 最大回撤 | 15.59% | 17.99% | +2.40pp |
| 年化波动率 | 18.39% | 15.90% | −2.49pp |

**判定：两套引擎对齐成功。** 独立数据源 + 独立执行模型下，两年总收益
差距 0.67pp、夏普差 0.03。残差与第四节差异清单逐项对应：回撤偏深、
波动偏低主要来自收盘撮合 vs 开盘撮合的半日 skew 与数据源复权差。
米筐的"基准收益 34.9%"是沪深300，与本对比无关（本地基准为池内等权）。

### 七(补). 三层逐笔对照的补充结论

用 `compare_run.py` 对 24 个调仓月做了目标组合反查 + 逐日权益对比：

- **研究层严格一致**：平台所选票在本地因子截面的排名全部落在 Top1~Top5，
  约 8/24 个月与本地 Top3 集合完全相同，其余多为 #3~#5 边界的近分差洗牌，
  无一例深排名偏离 → 因子窗口、日期对齐、复权方向均正确。
- **平台遇到买不起的高价票同样会空缺**（如 2025-11-03 目标 001309/603986
  均未成交，仅买入 600105），只是平台**静默跳过不记拒单**；本地的行为
  同向但会写入 rejections.csv。"平台更敢买"是早期误判，特此修正。
- **涨跌停判定时点已改为开盘口径**（core/limit.py）：引擎在开盘成交，
  判定基准应为"开盘这一刻还能不能成交"。样例窗口标记量：
  limit_up 892→186、limit_down 247→44（旧口径用收盘涨幅近似，
  含未来信息）。注意：该规则改动会让选股在动量强势月发生候选集变化，
  叠加小资金整手约束，净值路径可能出现大幅分叉——这是集中持仓策略的
  路径方差，不是引擎错误（曾误判 601138 三月缺席为盘中封板所致，
  实际是执行预算差 21 元被拒，详见 baseline/rejections.csv 可复算）。
- 权益曲线：期末差 0.5pp，中段最大 17pp（同一批动量龙头的不同子集）。
